🎲 Game Rule Object — Property Definitions (Human-Readable)

🧱 Core / Required Properties (Most Common)
	1.	id
A unique identifier for the rule (e.g., "rule_001").
	2.	name
A short, descriptive title of the rule (e.g., "Combat Resolution").
	3.	trigger
Describes the event or condition that activates the rule (e.g., "When a player draws a card").
	4.	context
Specifies the scope in which the rule applies, such as phase of the game, board area, or which players are involved.
	5.	effect
The outcome or action the rule performs. May include both plain language and structured actions.
	6.	componentsAffected
Lists the game elements influenced by the rule (e.g., "player_hand", "deck", "tokens").
	7.	source
The origin of the rule — e.g., "Core Rulebook", "House Rule", or "Expansion Set X".

⸻

🧩 Optional / Extended Properties
	8.	priority
Indicates the order of execution when multiple rules apply at the same time.
	9.	duration
Defines whether the rule is instant, temporary, or persistent (e.g., "instant", "until end of turn").
	10.	exceptions
Lists any special conditions where the rule does not apply.
	11.	dependencies
Specifies prerequisites or other rules that must be valid or active for this rule to work.
	12.	playerAgency
Describes whether players can make choices in response to the rule, and what options they have.
	13.	reversibility
States whether the effect of the rule can be undone or is final once executed.
	14.	version
Contains versioning info for rule tracking (e.g., introduced version, patch notes, errata).
	15.	meta
A collection of metadata, including:
	•	tags: Keywords to classify the rule.
	•	localization: Multilingual labels or translations.
	•	complexity: Relative difficulty (e.g., "simple", "medium", "complex").
	•	ruleType: Type of rule (e.g., "static", "procedural", "override").
	•	conflictResolution: Notes on what to do if this rule conflicts with others.
	16.	examples
A list of practical examples showing how the rule works in specific game situations.
